# ＡＩで作る自分専用アプリ作業ログ

## はじめに

最近、ちょっとした音楽ファイルを素早く確認するための小さなプレイヤーが欲しくなりました。

やりたかったことは、かなり単純です。

- MP3などの音楽ファイルをドラッグ＆ドロップしたらすぐ再生したい
- 小さなウィンドウで邪魔にならないように使いたい
- 再生、一時停止、前の曲、次の曲だけでいい
- ジャケット画像があれば表示したい
- プレイリストも簡単に扱いたい
- SRT字幕があれば歌詞のように表示したい
- できれば自分の作業スタイルに合わせて細かく育てたい

既存のメディアプレイヤーを探せば似たものはあります。  
ただ、実際に使ってみると「ここが少し違う」「この操作が重い」「この表示はいらない」「この機能だけ欲しい」という細かい不満が出てきます。

そこで今回は、**AIに相談しながら、自分専用のミニ音楽プレイヤーを作る**ことにしました。

アプリ名は仮に **DropMp3** としています。

---

## 作ったもの

DropMp3は、Python + PySide6で作った小型の音楽プレイヤーです。

基本操作はとても単純です。

1. 音楽ファイルをウィンドウにドラッグ＆ドロップする
2. すぐ再生される
3. リストに追加される
4. 必要ならミニプレイヤー化する
5. SRT字幕があれば再生時間に合わせて表示する

最初は「ドラッグ＆ドロップで音を鳴らすだけ」のつもりでした。  
しかし、使いながら要望を追加していくうちに、かなり実用的なミニプレイヤーになっていきました。

主な機能は以下のようなものです。

- 音楽ファイルのドラッグ＆ドロップ再生
- 複数ファイルのプレイリスト化
- プレイリストの並び替え
- 曲リストのドロワー表示
- 埋め込みジャケット画像の表示
- ジャケット画像をクリックで再生/一時停止
- ダブルクリックでミニプレイヤー化
- さらにタスクトレイ格納
- SRT字幕表示
- UTF-8 / Shift_JIS字幕の自動読み込み
- 字幕パネルの表示/非表示
- リピート Off / 1曲 / 全曲
- シャッフル
- 音量操作
- ランダム画像表示
- プレイリストの書き出し
- ジオメトリ保存
- EXE化用のPowerShellスクリプト
- ソース一式のバックアップスクリプト

ここまで来ると、単なるサンプルアプリではなく、かなり「自分用の道具」になります。

---

## なぜ作ろうと思ったのか

きっかけは、音楽ファイルを気軽に確認したかったことです。

AIで作った曲、作業中のBGM、素材として使う音声ファイルなどを、毎回大きなメディアプレイヤーで開くのは少し面倒でした。

たとえば、以下のような使い方を想定していました。

- 作業中に生成した音楽をすぐ確認する
- 複数のMP3を次々に試聴する
- ジャケット画像付きの曲を眺めながら再生する
- Whisperなどで作ったSRTを歌詞表示のように確認する
- 小さなミニプレイヤーとして画面の端に置く

普通のメディアプレイヤーでも再生はできます。  
しかし、ほしいのは高機能な万能プレイヤーではなく、**自分の作業にぴったり合った小さなツール**でした。

この「少しだけ欲しいものが違う」という部分こそ、AIで個人アプリを作る意味があると思います。

---

## 作業時間について

今回のDropMp3は、最初から設計書を作って一気に実装したものではありません。  
実際には、ChatGPTと会話しながら、動かして、直して、また動かして、という流れで少しずつ育てていきました。

体感としては、最初に「ドラッグ＆ドロップで音を鳴らすだけ」の版が動くまでがかなり早く、そこから使いながら細かい要望を足していった形です。

おおよその流れは以下のような感じです。

```text
最初の動く版:
  30分〜1時間程度

プレイリスト、ジャケット表示、ミニプレイヤー化:
  1〜2時間程度

字幕表示、ドロワー、タスクトレイ、EXE化、アイコン対応:
  さらに2〜3時間程度

細かいUI調整、ビルド・バックアップスクリプト、説明文作成:
  1〜2時間程度
```

合計すると、作業時間はだいたい **6時間前後** です。  
もちろん、その間ずっとコードを書いていたわけではなく、実際には「動かす」「気になる点を見つける」「ChatGPTに依頼する」「置き換えて試す」という確認作業が中心でした。

この点は、今回かなり印象的でした。  
従来なら、休日を丸ごと使っても途中で面倒になっていたような小物アプリが、会話しながら数時間で実用品に近づいていく。

このスピード感が、AIを使った個人開発の一番面白いところだと思います。

## CodexではなくChatGPTを使った理由

普段、コードを書く作業ではCodexのような開発支援AIも便利です。  
特に、既存プロジェクトに対する修正や、ファイル単位の差分編集には向いています。

ただ、今回のDropMp3では、あえてChatGPTとの対話を中心にしました。

理由は、単にコードを書かせたかったのではなく、**使いながら仕様を育てたかった**からです。

最初から完成形が決まっていたわけではありません。

「ドラッグ＆ドロップで再生したい」  
「やっぱりプレイリストも欲しい」  
「ミニプレイヤーにしたい」  
「右クリックメニューが欲しい」  
「字幕も表示したい」  
「タスクトレイにも入れたい」  
「EXE化したい」  
「配布用の説明文も欲しい」

という感じで、実際に動かしながら、次々に要望が出てきました。

このような作業では、コード生成能力だけではなく、

- 仕様を一緒に整理する
- UIの方向性を相談する
- 機能の優先順位を決める
- エラーの原因を推測する
- 全ソースを再構成する
- READMEや記事原稿も作る

といった、広い範囲の対話が必要になります。

ChatGPTはこの「相談しながら作る」流れに向いていました。

---

## ChatGPTで作るときの進め方

今回の進め方は、かなりシンプルです。

### 1. まず最小機能で動くものを作る

最初から完成版を目指さず、まずは以下だけをお願いしました。

- 小さなウィンドウ
- 音楽ファイルのドラッグ＆ドロップ
- 再生/一時停止
- 前の曲/次の曲
- シークバー
- 曲名表示
- ジャケット画像表示

この段階で重要なのは、「すぐ動くもの」を作ることです。

最初の一発で動くと、その後の改善がかなり楽になります。  
逆に、最初から全部盛りにすると、どこで壊れているのか分かりにくくなります。

---

### 2. 実行ログや画面キャプチャを貼って直す

実際に動かすと、すぐに細かい不満や問題が出ます。

たとえば、

- FFmpegのログがコンソールに出る
- ボタンの位置が気になる
- リストが見づらい
- 字幕パネルを閉じたい
- ウィンドウを閉じても音だけ残る
- タスクトレイに入らない
- アイコンが反映されない

こういうときは、ログやスクリーンショットをそのままChatGPTに渡しました。

人間が状況を説明しきれなくても、画面とログがあれば、AI側でかなり原因を絞ってくれます。

---

### 3. 「全ソース交換」で進める

小さな差分修正ではなく、途中からは「全ソースでください」と依頼しました。

これは個人開発では意外と有効でした。

理由は、差分だけだと自分が貼る場所を間違えることがあるからです。  
特に、PySide6のUIコードは、ウィジェットの配置やイベント接続が複数箇所にまたがります。

そのため、今回は以下のような進め方にしました。

```text
1. 現在のソースをバックアップ
2. ChatGPTから全文ソースを受け取る
3. dropMp3.pyを丸ごと置き換える
4. 実行して確認
5. 問題があればログを貼る
```

この方法だと、多少ソースが長くなっても、試行錯誤の速度が上がります。

---

### 4. バックアップスクリプトもAIに作らせる

全文ソース交換を何度も行うと、当然ながら過去の状態に戻したくなることがあります。

そこで、カレントフォルダの `.py`、`.ps1`、`.ico`、画像ファイルなどをまとめてZIP化するPowerShellスクリプトも作りました。

```text
oldsource/
  DropMp3_20260529_235334.zip
```

のように、日付付きでバックアップを残す形です。

こういう周辺ツールもAIに作らせると、個人開発がかなり楽になります。

アプリ本体だけでなく、

- ビルドスクリプト
- バックアップスクリプト
- 配布用README
- 機能説明
- 記事原稿

まで一緒に作れるのは、ChatGPTを使う大きな利点です。

---

## 作成過程で便利だった依頼の仕方

今回、特に有効だった依頼の仕方をまとめると、以下のようになります。

### 画面の状態を具体的に伝える

たとえば、

```text
リストとイメージの間にスプリッターを入れてください。
イメージは最小128x128まで小さくできるようにしてください。
終了時にスプリッター位置も保存してください。
```

のように、操作と期待結果を具体的に書きます。

### UIの位置を言葉で伝える

```text
歯車アイコンを一番右、ウィンドウ端に置いてください。
ワンショットボタンは歯車の左に置いてください。
```

このように「どこに置きたいか」を画面基準で言うと、AIも修正しやすくなります。

### エラーはそのまま貼る

PowerShellやPythonのエラーは、要約せずにそのまま貼る方が良いです。

```text
File cannot be loaded.
The file is not digitally signed.
```

のようなメッセージから、ExecutionPolicyやUnblock-Fileの話につながりました。

### 仕様変更は箇条書きにする

複数の変更を頼むときは、以下のように番号を付けると安定します。

```text
1. リスト表示中もヘッダーに曲名を出す
2. リスト側にDropした場合はその位置に挿入する
3. フッターに 10/500 のように表示する
4. SRTはShift_JISとUTF-8に対応する
```

AIにとっても、人間にとっても、チェックしやすくなります。

## 今回感じたAI開発の良さ

今回のような小さなアプリ開発では、AIの効果がかなり大きいです。

特に良いと思ったのは、以下です。

### 1. 思いついた機能をすぐ試せる

普通なら「面倒だからやめておこう」と思う機能でも、AIに頼めば試せます。

結果として、気軽に実験できるようになります。

### 2. UIの試行錯誤が速い

UIは、実際に触ってみないと分からないことが多いです。

今回も、

- リストは右クリックだけでよいか
- 左側ドロワーにした方がよいか
- 字幕はどこに出すか
- ミニプレイヤーに何を表示するか
- タスクトレイへどう格納するか

など、作りながら変えていきました。

AIを使うと、この試行錯誤の回転がかなり速くなります。

### 3. 周辺作業までまとめて頼める

アプリ本体だけでなく、

- EXE化
- アイコン作成
- ビルドスクリプト
- バックアップ
- README
- 機能説明
- 配布用文章

までまとめて相談できます。

これは、単なるコード補完とは違う強みです。

## 逆に注意した方がいいこと

もちろん、良いことばかりではありません。

### 1. ソースが大きくなると破綻しやすい

全文ソース交換は便利ですが、ソースが大きくなると、AIが一部を省略したり、過去の機能を落としてしまうことがあります。

そのため、以下は重要です。

- こまめにバックアップする
- 動いた版を残す
- 変更点を小さく区切る
- 直前のソースを必ず渡す
- 「既存機能を消さないで」と明示する

### 2. 実行確認は必ず人間が行う

AIが出したコードは、必ず実行して確認します。

特に、GUIアプリは見た目や操作感が重要なので、コードだけ見ても判断できません。

### 3. 仕様は人間が決める

AIはコードを書けますが、「何が使いやすいか」は最終的に自分で決める必要があります。

今回も、最初は単純なプレイヤーでしたが、使っているうちに「こうしたい」が増えていきました。

AIはその実装を手伝ってくれますが、方向性を決めるのは人間です。

## まとめ

今回、ChatGPTを使って自分専用のミニ音楽プレイヤーを作りました。

最初は、ドラッグ＆ドロップで音楽を鳴らすだけの小さなツールでした。  
しかし、実際に使いながら機能を追加していくことで、かなり便利な自分専用アプリになりました。

今回いちばん感じたのは、AI開発の本質は「コードを書いてもらうこと」だけではない、ということです。

むしろ重要なのは、

```text
自分の欲しいものを言葉にする
実際に動かす
不満を伝える
直してもらう
また使う
```

というループです。

このループが速くなることで、今までなら作らなかったような小さなアプリを作れるようになります。

大きなサービスや商用アプリでなくても、  
「自分だけが使いやすい道具」を作るには、AIはかなり相性が良いです。

もし、日々の作業で「この小さい不便を直したい」と思うことがあるなら、AIに相談しながら自分専用アプリを作ってみる価値はかなりあると思います。
